# Documentation product

## Register

product

## Users and purpose

Rust developers building Telegram clients and bots. Readers should be able to
start a client, select a session source, handle an error, and find the exact API
without reading the library internals first.

## Design principles

- Show a compiling example before explaining architecture.
- Separate ordinary setup from optional advanced controls.
- State lifecycle and persistence behavior precisely.
- Keep measured results distinct from live behavior and guarantees.
- Use short labels and substantive prose, without decorative slogans.

## Visual direction

The maintainer requested black backgrounds and restrained white liquid-glass
highlights. No blue accent. The crate diagram contains only crate names and
dependency arrows, without a title, subtitle, or footer.

## Accessibility

Readable high-contrast text, keyboard-visible focus, responsive navigation,
selectable code, and reduced-motion support. Documentation remains usable
without JavaScript.
