Getting started

grammers

Choose a session, configure the connection, and start. The managed client owns its sender tasks; the low-level API remains available when you need it.

Install from this fork

Use Git dependencies to get the fork APIs. Pin a reviewed commit with rev in a deployed application; main follows the verified integration branch.

Cargo.toml
[dependencies]
tokio = { version = "1", features = ["rt-multi-thread", "macros", "signal"] }

[dependencies.grammers-client]
git = "https://github.com/xD-Mohamed/grammers"
branch = "main"
features = ["session-file", "session-string", "session-import-files"]

Open a client

Opening the configuration reads local storage. Network work starts separately. An existing session can be reused; an empty session still needs login.

Rust
use grammers_client::{Client, SessionSource};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error + Send + Sync>> {
    let api_id = std::env::var("TG_ID")?.parse()?;
    let client = Client::builder(api_id)
        .session(SessionSource::file("account.session"))
        .build()
        .await?;

    client.start().await?;
    let authorized = client.is_authorized().await;
    let stopped = client.stop().await;
    let authorized = authorized?;
    stopped?;
    println!("Authorized: {authorized}");
    Ok(())
}

The compiled examples cover complete flows. A successful local build does not verify live account authorization.

Storage and portability

Choose the format explicitly

A filename and a session string are different inputs. The builder uses the selected decoder; it does not guess a format from arbitrary text.

SourceUse
SessionSource::file(path)This fork's SQLite session, opened or created for persistence.
SessionSource::memory()Temporary in-memory storage.
SessionSource::native(text)A grammers:1: portable session string.
SessionSource::pyrogram(text)An exported Pyrogram or compatible Kurigram string.
SessionSource::telethon(text)A Telethon v1 StringSession.
SessionSource::pyrogram_file(path)A supported Pyrogram/Kurigram SQLite session, read only.
SessionSource::telethon_file(path)A supported Telethon SQLite session, read only.
SessionSource::gotd_file(path)A gotd Loader v1 JSON file, read only.

Imported strings and foreign files become independent in-memory sessions. The source file is not migrated or overwritten. Unsupported database versions and unsafe active-journal states produce a clear error.

Native file sources also check the schema before writing. Open a closed, stable database without active SQLite sidecars. The lower-level SqliteSession::open remains available for application-controlled recovery of a known native database after an interrupted write.

Export the native format

Export works with every supported source, including Pyrogram, Telethon, and gotd. It reads the client's current session and returns a native string directly.

Rust
let session: String = client.export_session_string()?;
let restored = Client::builder(api_id)
    .session(SessionSource::native(session))
    .build()
    .await?;
Native v1grammers:1:<base64url payload and checksum>

The string contains the home DC's key, exact endpoints, and IP-family preference. It does not include peer caches, update checkpoints, or other DC keys. It is a login credential, not an encrypted backup. Use export_session_secret() when you want a wrapper with redacted Debug instead of a plain string.

For decoder APIs and supported file versions, see the session reference. The application's API ID always comes from your configuration, never from missing imported metadata.

Ownership

Start, stop, run

MethodBehavior
build().awaitValidate settings and prepare local storage. No network or background runner.
start().awaitStart the shared network driver once. Calls from clones share the same lifecycle.
stop().awaitStop accepting work and wait for shutdown. Repeated calls are safe.
run().awaitStart, establish the home connection, then wait for stop or a terminal failure.
run_until(future).awaitRun until a shutdown future resolves, then stop cleanly.
Wait for Ctrl+C
client.run_until(async {
    let _ = tokio::signal::ctrl_c().await;
}).await?;

stop is terminal. Build another client from the same session to restart. This prevents requests queued before shutdown from being replayed in a new connection lifetime. Existing manually driven SenderPool clients remain supported.

Settings

Keep ordinary setup in the builder

Group device information in DeviceConfig. Every field has a default. Set connection controls separately, without manually constructing a sender pool.

Rust
use grammers_client::DeviceConfig;

let client = Client::builder(api_id)
    .session(SessionSource::file("account.session"))
    .device(DeviceConfig {
        device_model: "Desktop client".into(),
        app_version: env!("CARGO_PKG_VERSION").into(),
        ..Default::default()
    })
    .build()
    .await?;

Request limits apply to SDK-owned work, including requests already sent. Canceling a caller does not pretend that its request disappeared from the network. IPv6 imports must use a compatible explicit preference.

Messages

Supply the essentials

A recipient and text are enough for a plain message. Advanced formatting and media remain available through InputMessage.

Rust
client.send_message(peer, "Hello").await?;

Set only the options you need

Rust
use grammers_client::SendOptions;

client.send_message_with_options(peer, "Hello", SendOptions {
    silent: true,
    ..Default::default()
}).await?;

SendOptions covers silent/background sending, draft clearing, link previews, media order, and reply IDs. Defaults match a plain InputMessage, including link previews disabled. Applying options preserves text, entities, media, markup, and scheduling, while replacing the six listed option fields.

Failure handling

Handle the error, keep the cause

RPC errors retain their Telegram code, name, and optional value. Category helpers distinguish waiting, authorization, capacity, transport, protocol, and storage failures without parsing a display string.

Rust
if let Err(error) = client.is_authorized().await {
    if let Some(wait) = error.retry_after() {
        eprintln!("Telegram requested a wait of {} seconds", wait.as_secs());
    } else {
        eprintln!("Request failed: {error}");
    }
}

A disconnected socket does not prove a request was never sent. Do not automatically replay a state-changing operation after an uncertain response. Keep runtime diagnostics enabled; a warning-free build does not mean network errors cannot occur.

Events

Own the update stream

The update receiver has one owner. Create a stream, process events in order, and synchronize its state before orderly shutdown. Catch-up requires the necessary peers in the session cache.

Rust
use grammers_client::sender::UpdatesConfiguration;

client.start().await?;
let receiver = client.take_updates()?;
let mut updates = client.stream_updates(
    receiver,
    UpdatesConfiguration { catch_up: true },
).await?;

// Process updates.next().await? in your application's loop.
updates.sync_update_state().await?;
client.stop().await?;

For command handling and filters, use the optional dispatcher. Raw updates and direct RPC access remain available for Telegram features without a high-level helper.

Transfers

Bounded work, explicit failures

Uploads support async streams. Large downloads use a bounded set of owned chunk futures. Canceling a download stops further scheduling, and failed chunks or filesystem writes return errors instead of leaving detached workers.

A canceled download may leave a partial destination file, and an operating-system write already issued cannot be rolled back by dropping a future. CDN redirects currently return an explicit unsupported error; complete CDN support is not advertised.
